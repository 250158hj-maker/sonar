# Sonar

**雑談で、自分の深さを測る。**

アイスブレークから、自分の信念や大切にしたい感情まで降りていく対話アプリ。
AI は次の問いを1つ出すだけで、**結論を言うのは常に本人**。
分岐の軌跡は、会話を跨いで1枚のマインドマップとして残る。

Rust / [Topcoat](https://github.com/tokio-rs/topcoat) / [Toasty](https://github.com/tokio-rs/toasty)（SQLite）/ Anthropic Claude Haiku 4.5。
学校の2学期 個人開発の**提出物⑨（プロジェクトのソースコード）**。発表は 2026-09-15。

---

## 解いている課題

**自分の考えを言葉にする必要が生じたのに、白紙に向かうと書き始められない人。**

属性ではなく状況で定義している——進路や転職を決める前、人間関係で迷ったとき、
選択の理由を説明できないとき。人口は広いが、引き金は鋭い。

その課題から、3つの制約が設計の芯として降りてくる。

| 制約 | 中身 |
|---|---|
| **AI は問いしか出さない** | 相槌・共感・要約・診断を出さない。「あなたは◯◯を大切にする人ですね」は、疑問文の形をしていても書かせない。境界（`Questioner`）が返せるのは**問いの文字列だけ**で、深掘り判定も所感もこの境界を通れない |
| **深さは本人が決める** | 深掘りは「降りるべき道」ではなく「降りられる道」。ひとことで終わった会話も失敗ではない。入口で1回だけ聞く「いまの気分」が掘り方を変え、それ以外にユーザーへ深さの操作を見せない |
| **地図に残るのは本人の言葉だけ** | ノードに入るのは回答そのもので、AI の要約は入らない。ノードの縦位置が「自分がどこまで辿ったか」をそのまま表す |

「やらないこと」と縮退の順序は [`docs/scope.md`](docs/scope.md)（正典）が持つ。

## 3つの画面

| 画面 | パス | 中身 |
|---|---|---|
| ホーム | `/` | 入口は「話す」の1アクションだけ。これまでの回数・地図に残った言葉の数と、地図のミニプレビュー。会話0件のときは統計もプレビューも出さない |
| 対話 | `/talk` | 気分を1回選んで始める。問いは SSE で流れてきて1文字ずつ出る。「ここまでにする」を常に見える位置に置く |
| 地図 | `/map` | 会話を跨いだ全体表示（わたしを中心にした放射状）と、1本を開いたときの深さの表示 |

## 1ターンの流れ

```
ブラウザ ── POST /talk/answer ─────▶  store       回答を保存し node_id を返す
         ◀── {conversation_id, node_id} ──┘
         ── GET /talk/question?node= ──▶  store::path_to  根までの履歴を引く
                                      └▶  questioner     Anthropic Messages API（stream）
         ◀────── SSE: delta… / done | failed ──────┘
```

**回答の保存と問いの生成を2リクエストに割ってある。** `EventSource` が GET しか発行できない
という制約から始まった分割だが、結果として「**2つのリクエストの間でブラウザが死んでも、
回答は保存済みで、無いのは問いだけ**」という保証が構造になった。
だから失敗時の「もう一度」は POST をやり直さない（→[`src/pages/talk.rs`](src/pages/talk.rs) 末尾のコメント）。

サーバは会話の途中状態を持たない。ブラウザに出した問いは、次の回答と一緒に送り返してもらう。

## 動かす

```bash
git clone https://github.com/250158hj-maker/sonar.git && cd sonar
```

### 前提

| | |
|---|---|
| Rust | **1.95 以上。** `edition = "2024"` は 1.85 からだが、`topcoat` と `toasty` が `rust-version = "1.95"` を宣言しているので、それ未満は cargo がビルド前に弾く。開発機は 1.96.0 stable |
| `topcoat-cli` | **0.6.2 に固定。** `Cargo.toml` が固定しているのは**ライブラリ**であって CLI ではないので、別に入れる |
| `ANTHROPIC_API_KEY` | 2問目以降の生成に要る。**無くても通しで触れる**（下記） |
| Node.js | L2 の検査（`check/*.mjs`）を走らせるときだけ |
| Python 3 | L3・L4 の検査と `dev/seed.py` を走らせるときだけ。**標準ライブラリのみ**で、追加インストールは要らない |

```bash
cargo install topcoat-cli --version '=0.6.2'
```

> zsh では `=0.6.2` がコマンド名解決に食われて失敗する。**クォートする。**

### 起動

```bash
PORT=3100 topcoat dev
```

`http://localhost:3100` を開く。**`cargo run` では起動しない**——アセットのバンドルを作るのは
CLI 側で、素で起動すると `AssetBundle::load()` で落ちる。

| 環境変数 | 既定 | 用途 |
|---|---|---|
| `ANTHROPIC_API_KEY` | （なし） | Anthropic Messages API のキー。プロセス起動時ではなく**問いを作る直前**に読む |
| `SONAR_DB` | `./sonar.db` | SQLite のファイルパス |
| `PORT` | `3000` | 待ち受けポート |
| `HOST` | `127.0.0.1` | WSL から Windows のブラウザで開くだけなら**変えなくてよい** |

`PORT` / `HOST` を読むのは CLI ではなく topcoat ライブラリ本体（`topcoat::start()` の中）。
`PORT=3100` は開発機の都合（3000 を別プロジェクトが使っている）なので、`topcoat dev` だけでも 3000 で起動する。

DB は初回起動時に自動で作られる（`[schema] 新規作成した (…)` と出る）。準備は要らない。

**`ANTHROPIC_API_KEY` が無くても通しで触れる。** 1問目は LLM を呼ばず、気分ごとの固定文
（`src/script.js` の `MOODS[*].opener`）を出すため。実測：`/`・`/talk`・`/map` は 200、
`POST /talk/answer` も 200 で回答が保存され地図に点が置かれる。500 になるのは
`GET /talk/question`（＝2問目）だけで、画面には「うまく問いを作れませんでした」が出る。

> **マイグレーションを使っていない。** Toasty 0.7 には `migration` フィーチャがあるが有効にしておらず、
> スキーマは `push_schema()` で作る。これは `IF NOT EXISTS` の無い `CREATE TABLE` を発行するので、
> 起動時に DB ファイルの有無を見て**新規のときだけ**呼んでいる（判定は接続より前。
> SQLite は接続した時点でファイルを作ってしまうため）。**モデルを変えたら DB ファイルを消して作り直す。**

起動まわりの詳細と、**踏むと分かっている罠の一覧**は [`docs/next.md`](docs/next.md) §1・§3 が正典。
ここには「クローンして動かすまで」に要るものだけを置いている。

## 検査

| 層 | 走らせ方 | 対象 |
|---|---|---|
| **L1** | `cargo test` | Rust の純関数（`Mood` / `steer` / `drain_frames` / `push_utf8` / `jp_date`・`key`）26件 |
| **L2** | `node check/typing.mjs` ／ `preview.mjs` ／ `map.mjs` | `src/script.js` を DOM スタブの上で実際に走らせる 14件 |
| **L3** | `python3 check/httpcheck.py` | HTTP と DB の不変条件 26件。**アプリ側でしか担保できない制約**（1会話に1手目は1つ／気分は5値／他人のセッションに触れない）はここが見る |
| **L4** | `python3 check/run.py <mood>` | 問いの形。**API を叩くので課金が発生する**（1本 $0.00623 実測）。むやみに回さない |
| **L5** | ブラウザで手動 | 通し・応答速度・地図の操作 |

L3 は使い捨ての DB と別ポートに向ける。**キーを外して起動すれば課金ゼロで走る**——
`/talk/question` を叩く項番も、LLM に到達する前（クエリ検証・所有確認・履歴の組み立て）で決着するため。

```bash
rm -f /tmp/sonar-test.db && env -u ANTHROPIC_API_KEY PORT=3199 SONAR_DB=/tmp/sonar-test.db topcoat dev
```

```bash
python3 check/httpcheck.py
```

現在 **79項目中 71合格・2不合格・6未実施**。不合格2件はどちらも「問いの形」（L4）で、機構まで
特定したうえで**直さないと決めている**。未実施6件はブラウザ操作と発表当日の第三者テスト。
項目表と判断の根拠は [`docs/test.md`](docs/test.md)。

検査は**本番と同じものを見る**。プロンプトは `src/prompt/system.md`、地図は `src/script.js` を
直に読み、テスト用の写しを作らない。写しを持った瞬間、検査が「自分の嘘」を検査し始める。

### 地図が育った状態を見る

`dev/seed.py` が種データを入れる。LLM は呼ばないので課金は発生しない（確かめたいのは
描画であって問いの品質ではない。品質の検査は `check/run.py` が持つ）。

**順序に依存する。** seed は `CREATE TABLE` を持たないので**先に一度アプリを起動してスキーマを作る**必要があり、
`--into` にセッションIDを渡さないと、ブラウザの Cookie とひも付かず**空の地図に見える**。

1. `PORT=3100 SONAR_DB=/tmp/demo.db topcoat dev` で起動して、1問だけ答える
2. DevTools で Cookie `sonar_sid` の値を控える
3. 種を入れて `/map` を再読み込みする

```bash
python3 dev/seed.py --db /tmp/demo.db --into <sonar_sid> --conversations 40
```

## リポジトリの構成

```
src/
  main.rs             ルータ組み立て・DB接続・app_context。単一プロセスで、ジョブもキューも無い
  models.rs           Conversation / Node / Mood。Toasty で張れない制約はここと store で担保する
  store.rs            DB に触る唯一のモジュール。会話の1手目を作る入口もここだけ
  questioner.rs       Questioner トレイトと Anthropic 実装。返すのは問いの文字列だけ
  mapdata.rs          window.SONAR の組み立て。地図とホームのプレビューが同じデータを見る
  ui.rs               doc_head / site_header / 表示モードのちらつき防止
  pages/
    home.rs           /
    talk.rs           /talk と POST /talk/answer・GET /talk/question（SSE）
    map.rs            /map
  prompt/system.md    system プロンプトの正典。Rust も check/run.py も実行時にこれを読む
  script.js           地図の描画・逐次表示・テーマ。外部ライブラリを使わない（1,608行）
  style.css
check/                自動検査。*.mjs は L2、httpcheck.py は L3、run.py は L4
dev/seed.py           地図が蓄積したときの見え方を確かめる種データ。LLM を呼ばない
docs/                 Obsidian Vault からの一方向コピー。編集しない（下記）
```

DB は2テーブルだけ。`Conversation`（セッション・気分・開始時刻）と、自己参照する `Node`
（`parent_id IS NULL` がその会話の1手目）。**深さのカラムは持たない**——根からの距離で決まるものを
保存すると、木と数値の二重管理になる。

## 技術選定

| 決定 | 根拠（要約） | ADR |
|---|---|---|
| **Rust + Topcoat 0.6.2** | Next.js のほうが客観的に完成確率は高い。それでも採らないのは、このプロジェクトの価値が成果物だけでなく「Rust で作りきった経験」にあり、評価軸が「チャレンジングならそれ相応」だから。**代わりに版を固定し、縮退条件を先に決めて封じ込めた** | [ADR-0001](docs/adr/0001-tech-stack.md) |
| **Claude Haiku 4.5** | 出力が毎回150トークン程度で、フロンティアモデルの推論を要さない。Gemini 無料枠は「入力がモデル改善に使われうる」——**信念や感情を開示するアプリの前提と正面から衝突する**。有料に上げてオプトアウトすると単価で負けるので、Gemini を選ぶ合理的な位置が存在しない | [ADR-0002](docs/adr/0002-llm-provider.md) |
| **別々の会話を合流させない** | 全部を1枚に描くと会話8〜10回で当たり判定が重なる（実測）。**全体表示を会話単位で畳む**と、1画面の点の数が会話数で決まる。木のまま保てるので合流ロジックも要らない | [ADR-0003](docs/adr/0003-map-data.md) |
| **描画ライブラリを入れない** | 地図はモックから移植した自前の SVG 描画。座標計算に手を入れないことを制約として先に決めてある | [ADR-0003](docs/adr/0003-map-data.md) |
| **WSL2 で開発・ドキュメントは Vault** | コードは提出物⑨、設計書は別の提出物。Vault 全体は提出物にできないので、参照用の写しだけを `docs/` へ一方向に生成する | [ADR-0005](docs/adr/0005-dev-env.md) |

ADR は**内省の記録ではなく、決めたことを蒸し返さないためのメモ**。そこで否決された案を再提案しない。

## データの扱い

**対話の内容は SQLite にそのまま保存され、2問目以降は Anthropic API に送られる**
（履歴は根からのパスを毎回まとめて送る）。地図に残るのは本人が発した言葉そのもの。

- DB ファイル（`sonar.db` / `demo.db`）は `.gitignore` で追跡外。**対話ログはリポジトリに入らない**
- 認証は無い。会話の持ち主は Cookie（`sonar_sid`）だけで決まる
- **会話を消す UI は無い。プライバシー告知も未実装**。他人に触ってもらう場では、
  この2つが無いことを口頭で伝える前提で運用している（→[`docs/usertest.md`](docs/usertest.md)）

このリポジトリは学校の提出物であり、**ライセンスを設定していない＝著作権は全て留保**している。
閲覧のための公開であって、再利用を許諾するものではない。
