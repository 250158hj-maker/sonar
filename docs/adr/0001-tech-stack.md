## 2. 文脈

### 前提

- 目的は学校の2学期 個人開発 定期試験。**完成させることが唯一の目的**であり、そのために機能を諦めることは厭わない（→[スコープと縮退ライン](../scope.md) §3）
- Rust が好きな言語であり、新しい技術に挑戦したい意思がある
- 評価軸は「完成度ではなく、題材に対してどれぐらい取り組めたか。チャレンジングならそれ相応な評価」（→『2学期定期試験 項目』）
- 過去3プロジェクトが中止・凍結・未着手で終わっている（→[スコープと縮退ライン](../scope.md) §0）。**技術的野心がプロジェクトを殺した実績がある**

### 調査で確定した事実（2026-08-26 時点）

| 事実 | 出典 | 本件への影響 |
|---|---|---|
| **SSE / WebSocket は `full` フィーチャでサポート済み**。Datastar 統合もある | [GitHub](https://github.com/tokio-rs/topcoat) | 🟢 LLM トークンの逐次表示が実装できる |
| ロードマップ未実装：認証・バックグラウンドジョブ・**streaming SSR / Suspense**・バリデーション | GitHub README | 🟢 未実装の「streaming SSR」は初期HTMLの分割配信であり、SSE とは別物。混同しない |
| Toasty は 2024-10 発表・~~現 0.6.x~~ **現 0.10.0**（2026-08-30 再確認）。SQLite / PostgreSQL / MySQL / Turso / DynamoDB 対応 | [tokio.rs](https://tokio.rs/blog/2024-10-23-announcing-toasty) | 🟢 DB層は Topcoat 本体より成熟。DB設計の提出物に耐える |
| Axum / tokio 上に構築 | [tokio.rs](https://tokio.rs/blog/2026-07-22-announcing-topcoat) | 🟢 `reqwest` がそのまま使える。**AI連携はFW選定の障害にならない** |
| **Rust→JS に変換できる型の語彙が小さく、複雑なクライアントロジックはすぐ境界に当たる** | [XenoSpectrum](https://xenospectrum.com/en/topcoat-rust-fullstack/) | 🔴 対話的マインドマップが直撃する |
| ランタイムが `new Function()` を使い、CSP の `unsafe-eval` 禁止環境で動作しない | 同上 | 🟡 学内提出では無害 |
| **0.1.0→0.5.0 の11日で破壊的変更41件**。最新 0.6.2（2026-08-18）、累計DL 10,385 | [crates.io](https://crates.io/crates/topcoat) | 🟠 バージョン固定で無効化可。残るのは「詰まっても情報が無い」リスク |
| Anthropic に**公式 Rust SDK が存在しない** | crates.io / GitHub | 🟡 非公式crateは学期中に壊れうる。直叩きする |

### リスクの所在

当初「AI連携が Topcoat 採用の障害になるのでは」と疑ったが、**それは誤りだった**。Anthropic API 呼び出しは HTTP + SSE であり、Topcoat は Axum/tokio 上なので `reqwest` がそのまま動く。フレームワークがほぼ関係しない層である。

**本当のリスクは対話的マインドマップ**である。パン・ズーム・ノード選択は、Topcoat の Rust→JS 語彙制限が唯一直撃する機能だった。

## 3. 検討した代替案

### 3-1. Next.js（TypeScript / React）— 棄却

**これは客観的に、完成確率が最も高い選択肢である。** 慣れた技術スタックであり、情報量も桁違いで、詰まっても必ず答えが見つかる。マインドマップのJS実装との統合も最も素直。

にもかかわらず採らない理由：

- 本プロジェクトの価値は成果物だけではなく、**Rust で作りきった経験**そのものにある。ここを外すと、そもそもこのテーマを選んだ理由が消える
- 評価軸が「チャレンジングならそれ相応な評価」であり、既に慣れたスタックでの実装は評価上の上限が低い

**このトレードオフを認識した上で、追加リスクを受け入れる。** ただし無条件ではなく、§5 の採用条件と §6 の縮退条件で封じ込める。**「やっぱり Next.js にしよう」は蒸し返さない。** 蒸し返したくなったら、それは縮退ライン（§6）を発動すべき局面である。

### 3-2. Leptos — 棄却

Rust のフルスタックFWとしては Topcoat より成熟している。しかし：

- WASM ベースであり、ビルドチェーンとバンドルサイズの複雑さを持ち込む。本アプリはSSR中心で、WASM が買えるものが少ない
- 足回り（セッション・アセット・Tailwind・UIコンポーネント）を自分で組む量が Topcoat より多い。**完成優先の方針と逆行する**

### 3-3. Axum + htmx — 棄却（ただし縮退先として採用）

最も安定しており情報も多い。しかしテンプレート・セッション・アセットパイプライン・Tailwind をすべて自分で組む必要があり、着手コストが高い。

**採らないが、捨てない。** Topcoat は Axum の上に構築されているため、Toasty・`reqwest`・地図のJS・DB設計はそのまま持ち越せる。§6 の縮退先として正式に位置づける。

## 4. 決定の根拠（3視点）

- **開発者**：SSE と Toasty の存在により技術的成立性は調査で確認済み。バージョン固定で破壊的変更を無効化できる。唯一の構造的な壁（Rust→JS 語彙制限）は、マインドマップを**素の JavaScript** へ外出しすることで回避できる——これは妥協ではなく「UIとロジックの分離」そのもの
- **クライアント（評価者）**：評価軸が「取り組み度」と「内省」である以上、公開1ヶ月のFWを選び、制約に当たって設計判断を残すこと自体が加点対象になる
- **経営者**：期間は2学期の約3ヶ月、リソースは1人、締切は毎週来る。最大コストは「FWの学習」ではなく「**詰まったときに情報が存在しないこと**」（累計DL 1万＝ネットに答えが無い）。これを §5-1 と §6 で封じる

## 5. 決定の帰結（採用条件・これは制約である）

1. **`Cargo.toml` で `=0.6.2` に完全固定する。** 学期中は上げない。新機能は必要ない
2. **マインドマップは Rust→JS 反応性に載せない。** 素の JavaScript で実装し、Topcoat は HTML と静的アセットを配る役に徹する（外部ライブラリは不要。→[スコープと縮退ライン](../scope.md) §6）
3. **LLM 呼び出しは `reqwest` で直叩きする。** 非公式crateに依存しない
4. **認証は実装しない。** 匿名セッションのみ。これは制約への妥協ではなく、自己開示アプリとして正しい設計判断（登録要求は最大の離脱要因）
5. **スパイクを実装フェーズの最初に置く。** 特に「素の `.js` を配信できること」を最優先で潰す（→[ドキュメントハブ](../status.md)）
6. **Toasty も `=0.7.0` に完全固定する**（2026-08-31 追加）

### 5-6. なぜ最新の Toasty 0.10.0 を採らないか（2026-08-31）

Toasty は本ADRの調査時点（2026-08-26）で「現 0.6.x」としていたが、**実際には 0.10.0 が出ていた**。にもかかわらず `=0.7.0` を採る。

| 案 | 判断 |
|---|---|
| **`=0.7.0`** | **採用。Topcoat `=0.6.2` の `examples/toasty-todo` が対象にしているのがこれ**（Topcoat 側 workspace の `toasty = "0.7"`）。**唯一手元にある「動く参照」と同じ版になる** |
| `=0.10.0`（最新） | 却下。**同じ版で書かれた example が存在しない。** Toasty は 0.x で、マクロの属性構文は版間で変わりうる。詰まったとき照合先が無い |

**これは §5-1（Topcoat を `=0.6.2` に固定）と同じ判断である。** §4 の経営者視点が挙げた最大コストは「詰まったときに情報が存在しないこと」で、**新しい版を選ぶことは、その唯一の対策を自分から捨てる行為**にあたる。

**フリーズは 9/8、発表は 9/15。「あとで上げる」という時間は存在しない。** 上げる価値があるとすれば来学期以降の話であり、その判断はこのプロジェクトの外にある。

> 実際 `=0.7.0` でスパイク3は同日中に通り、[設計書 データベース](../design/database.md) §10 の6項目すべてに答えが出た。
