## 3. 決定の根拠

1. **同じ仕事で最も安い。** Gemini 3.5 Flash 有料と比べて約37%安い（$0.055 対 $0.087）
2. **無料枠の代償が、このプロダクトの前提と正面から衝突する。** Sonar はユーザーが**信念や大切にしたい感情を開示する**アプリである。その入力がモデル改善に使われうる条件は、企画の根幹と両立しない。そして有料枠に上げてオプトアウトした瞬間、単価で Haiku 4.5 に負ける——**Gemini を選ぶ合理的な位置が存在しない**
3. **挙動を知っている。** 完成が唯一の目的である以上（→[スコープと縮退ライン](../scope.md) §0）、既知の挙動はリスク低減として正当な選定理由になる（経営者視点）
4. **Claude Code と同一ベンダー。** APIキー・請求・ドキュメントが1系統で済む
5. **技術的な難易度差が無い。** Rust には Anthropic・Google どちらも公式SDKが存在せず、`reqwest` での HTTP + SSE 直叩きになる。Gemini に技術的優位は無い

### 無料枠を捨てるコスト（正直な計算）

開発中の試行を500ターンと見積もると、$0.0028 × 500 = **約 $1.4（¥200程度）**。判断を動かす額ではない。「無料だから」という理由は、この規模では成立しない。

## 4. 検討した代替案

### 4-1. Gemini 3.5 Flash 無料枠 — 棄却

開発中のコストがゼロになるのは事実であり、自腹の個人開発では魅力的である。しかし §3-2 のとおり、**このアプリが扱うデータの性質と両立しない**。加えて §3 の計算どおり、節約額は¥200程度にすぎない。

**開発・検証中に限れば許容できる**（テスターに事前に伝えることが条件）。だが本番の前提にはできず、企画書・プレゼンで説明できない状態を作る。**最初から有料枠で作る。**

### 4-2. Claude Sonnet 5 — 棄却（ただし部分採用の余地を残す）

質問の言い換えの自然さは Haiku 4.5 より上のはずである。しかし1セッション $0.11 で **§7 の予算を超える**。

**まず Haiku 4.5 で作る。** 実際に会話してみて質問が機械的すぎる場合に限り、Sonnet 5 に上げることを検討する。§1 の trait 分離があれば、差し替えは `Questioner` の実装1つで済む。ただし呼び出しが1つしか無い以上、**上げれば全ターンが Sonnet 5 になる**。1セッション $0.11 で §7 の予算を超えるので、上げるなら予算のほうを見直す判断が要る。

### 4-3. ローカルLLM — 棄却

コストはゼロでプライバシー問題も消える。しかし応答速度が §7 の「初回トークン3秒以内」を満たせる保証がなく、デモ機の性能に品質が依存する。**完成優先の方針に対してリスクが大きすぎる。**

---

## 5. 決定の帰結

1. **LLM呼び出しは trait の裏に置く。** プロバイダ固有のコードを1箇所に閉じ込め、差し替えを config レベルの変更で済ませる
2. **APIキーは環境変数で管理し、リポジトリに含めない**
3. **モデルIDは `claude-haiku-4-5`**（日付サフィックスは付けない）
4. **コストが §7 の予算を超えた場合の最初の手段は、履歴の送り方を変えること**（全文再送 → 要約＋直近数ターン）。モデルを下げるのではなく、入力トークンを減らす
5. **プロンプトキャッシュは使わない**（2026-08-27 訂正）

> **【注意】「1,024トークンを超えるなら検討する」は誤りだった**
> 最小キャッシュ長は**モデルごとに違い、しかも世代順に単調ではない**。1,024 は Sonnet 系の値であって、**Claude Haiku 4.5 は 4,096トークン**である（参考：Claude Opus 5 は 512）。
>
> Sonar の system プロンプトは約900トークン（→[設計書 プロンプト](../design/prompt.md) §3）で、桁が足りない。
>
> **危険なのは「効かない」ことではなく、「効かないのにエラーが出ない」ことである。** `cache_control` を付けても 400 は返らず、`cache_creation_input_tokens: 0` が静かに返るだけなので、**付けたまま効いているつもりになる**。だから「短いから効かない」ではなく「**使わない**」と決めておく。

6. **課金は前払いクレジット。初回は $5 だけ買う**（2026-08-27 決定）
7. **Haiku 4.5 の提供終了は「2026-10-15 より前にはならない」**。9/15 の発表には影響しないが、ラインナップ中で最も近い日付である

### 課金の形（2026-08-27 調査）

**「従量課金 か プリペイド か」ではない。2つは別の軸である。**

| 軸 | Claude API |
|---|---|
| 金額の決まり方 | **従量**（トークン単価 × 使用量） |
| 支払いのタイミング | **前払い**（クレジットを買ってから使う） |

同じ従量単価の Claude Platform on AWS は「後払いのみ・前払いクレジット無し」と明記されている。**単価の決まり方と支払いのタイミングは独立している。**

この区別が実務に効くのは、**$5 が「買った枠」ではなく「露出の上限」**だという点である。定額なら $5 でできることが決まるが、従量なので**減る速さは使い方で決まる**。だから上限設定に意味がある。

**運用の3点。**

| 決めたこと | 理由 |
|---|---|
| **Auto-reload は切る** | 自腹である。残高が尽きて 400 が返るほうが、知らないうちに補充され続けるより安全。**止まる側に倒す** |
| **Spend limit を $10 に張る**（Console の Billing ページ） | tier の月間上限（Start = $500）とは別に、自分で低い上限を設定できる。プロジェクト全体の見積が $1.5〜2 なので $10 で足りる |
| **初回購入は $5。足りなければ足す** | クレジットは**購入から1年で失効・返金不可**。まとめ買いに利点が無い |

**$5 の余裕**：6ターンの会話（$0.009）なら約555回、20ターンの会話（$0.053）でも約94回。プロジェクト全体の見積に対して2.5〜3倍。

### レート制限は当たらない（2026-08-27 確認）

Start tier（初期）の Haiku 4.5 は **1,000 RPM / 2,000,000 ITPM / 400,000 OTPM**。Sonar は同時接続1（→[スコープと縮退ライン](../scope.md) §7）なので、**桁が違いすぎて当たらない**。

> **【注意】新規組織は Evaluation tier から始まることがある**
> 使用履歴が無い組織には、不正利用対策として**標準より低い制限**が課される場合がある。履歴が溜まれば自動で上がる。
>
> **9/15 のデモ直前に初めてキーを作ると、ここに当たりうる。** 8/30 までにキーを作って [設計書 プロンプト](../design/prompt.md) §9 の25問を叩いておくことが、そのまま履歴づくりになる。

## 6. 蒸し返さないこと

**「無料だから Gemini にしよう」は蒸し返さない。** 節約額は¥200程度であり、その対価としてユーザーの開示データがモデル改善に使われうる状態を受け入れることになる。この計算は §3 で済んでいる。

コストが問題になったときの手段は §5-4（入力トークンを減らす）であって、プロバイダの変更ではない。

**「まとめて買っておけば安心」も蒸し返さない。** クレジットは1年で失効し返金されないので、**買いすぎは純粋な損失**である。単価は買う量で変わらない（ボリューム割引は個別交渉の世界で、この規模には無い）。
