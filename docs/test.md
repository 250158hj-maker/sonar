## 1. テスト計画

### 1-1. 何を守るためにテストするか

**このプロジェクトが実際に踏んだ失敗は3種類あり、それぞれ別の手当てが要る**（→[詳細設計書](detail.md) §7・§8・§9）。テストの目的をこの3つに絞る。

| # | 失敗のクラス | 実際に起きたこと | 手当て |
|---|---|---|---|
| 1 | **検査が無い** | `initMap` を走らせる検査が1本も無く、`ReferenceError` で地図が丸ごと死んだまま commit した | 走る経路すべてに、最低1本は「例外を投げずに完走する」検査を置く |
| 2 | **検査はあるが、スタブが本物を真似ていない** | `cancelAnimationFrame` がハンドルを無視してキュー全体を捨て、レイアウトの遷移を一度も検証していなかった | スタブの既知の落とし穴を §3-3 に列挙し、新規スタブは同じ罠を踏まない |
| 3 | **検査は正しく動くが、見ている対象が本番と違う** | `check/run.py` が正典ではない旧本文の system プロンプトを読み続けていた | 検査は**本番と同じファイル**を読む。写しを作らない |

> **【重要】検査が通ったことと、規則が守られていることは別である**
> これが実装フェーズでいちばん効いた学び（→[詳細設計書](detail.md) §6）。したがって項番71（検査をわざと壊して終了コード1になるか）を項目表に入れてある。**検査が検査になっていることを確かめないと、通っていることに意味が無い。**

### 1-2. 合格の定義

| 結果 | 意味 |
|---|---|
| 合格 | 期待結果と実際の結果が一致した |
| 不合格 | 一致しなかった。**備考に実際の結果を書く**（直したかどうかは別の話） |
| 未実施 | まだ走らせていない |

**不合格をゼロにすることは目標ではない。** 定期試験の最大の評価対象は内省であり（→『2学期定期試験 項目』）、不合格とその原因が残っているほうが記録として価値がある。実際、項番40・66・67 は**不合格になる見込みが高いと分かったうえで**入れてある。

### 1-3. テストしないと決めたもの

**影響範囲・優先度・コストで切る。** 落としたものは黙って落とさず、理由とセットでここに残す。

| 対象外 | 理由 |
|---|---|
| LLM が返す問いの**内容**の正しさ | 測れない。測るのは**形**だけ（Yes/No でない・二択でない・NG語が無い・長さ）。内容の妥当性を測ろうとした時点で診断の妥当性検証に踏み込む（→[スコープと縮退ライン](scope.md) §2） |
| スマートフォン幅 | 2026-08-30 に取り下げ済み。テストは PC で渡す（→[第三者テスト台本 20260909](usertest.md) §5） |
| スクリーンリーダーでの木構造の読み上げ | 未検証。**「未検証」と正直に書くほうが価値がある**（→[詳細設計書](detail.md) §9） |
| 同時利用・SQLite の同時書き込み | 想定していない。学内デモの規模で発生しない |
| 削除UI・マイグレーション | **作っていない。** 無いものはテストできない（→[詳細設計書](detail.md) §9） |
| 性能の上限探索 | 会話400本・DOM 1201ノードまで実測済みで足りている（→[詳細設計書](detail.md) §6）。上限を探しても使う場面が無い |
| Cookie の `Secure` 属性 | dev が `http://localhost` なので付けられない。**本番なら採用できない割り切り**として[詳細設計書](detail.md) §4-4 に記録済み |

## 2. テストの層と走らせ方

```
cargo test                                    L1  Rust の純関数（現在0件 → 新設）
node check/{typing,preview,map}.mjs           L2  script.js（DOMスタブ。既存3本）
python3 check/httpcheck.py                         L3  HTTP＋DB の不変条件（新設）
python3 check/run.py <mood>                   L4  問いの形（既存。課金あり）
ブラウザで操作                                  L5  通しと運用（手動）
```

| 層 | 対象 | 走らせ方 | 項番 | 現状 |
|---|---|---|---|---|
| **L1** | `Mood` / `steer` / `drain_frames` / `jp_date` / `key` | `cargo test` | 1〜24 | **0件。全部これから** |
| **L2** | `initMap` / `initTalk` / `initPreview` | `node check/*.mjs` | 51〜64 | 3本あり。**13件が合格済み**（2026-08-31 実行） |
| **L3** | `POST /talk/answer` / `GET /talk/question` / `/map` / `/` / 木構造 | `python3 check/httpcheck.py` | 25〜50 | **無い。新設** |
| **L4** | 問いの形 | `python3 check/run.py <mood>` | 65〜70 | あり。**課金が発生する** |
| **L5** | 通し・応答速度・地図の操作・第三者テスト | 手動 | 71〜77 | 台本あり |

> **【注意】L3 が最大の空白**
> **アプリ側でしか担保できない不変条件**（1会話に1手目は1つ／気分の5値／他人のセッションに触れない）は、いま**どの自動検査も見ていない**。型と `store.rs` の単一入口で守っているだけで、壊れたことを知る手段が無い——§1-1 の失敗クラス1そのものである。**着手の優先度はここが最も高い。**

## 3. Claude Code（WSL）への実装契約

**この節が「テストケースを書く」ときの唯一の指示書。** ここに書いていないことは §4 の表から読み取る。

### 3-1. 置き場所

| 層 | 置き場所 | 理由 |
|---|---|---|
| L1 | **対象モジュールの末尾に `#[cfg(test)] mod tests`** | `drain_frames` が private。`tests/` ディレクトリ（結合テスト）からは見えない。バイナリクレートなので `cargo test` はこの形で拾う |
| L2 | `check/<name>.mjs` | 既存3本と同じ場所・同じ形 |
| L3 | **`check/httpcheck.py`（新設）** | 下記 |
| L4 | `check/run.py`（既存。触らない） | API を叩くもの（項番65〜69）だけ |
| L4 のうち `check/run.py` に置けないもの | **`check/httpcheck.py`** | 項番70 は「`run.py` が読むパスの確認」で API を叩かない。**項番36 は API を叩く**が、中身は HTTP の経路検査なので置き場所は L3 と同じでよい。どちらも `run.py` に足すと「触らない」に反する。**課金ありは `BILLED` に入れ、項番を明示したときだけ走らせる**（2026-09-01 追加） |

> **【注意】ファイル名は `httpcheck.py`。**`http.py` にしない****
> 当初 §3-1 は `check/httpcheck.py` を指定したが、その名前は**標準ライブラリの `http` パッケージを隠す**。
> スクリプトとして起動すると `sys.path[0]` が `check/` になり、`import http.cookiejar` が自分自身を掴んで
> `'http' is not a package` で落ちる。**§3-2 が「依存を足さない」ために標準ライブラリを選んだのに、
> 名前がその標準ライブラリと衝突していた。** 2026-09-01 に改名し、`sys.path` を書き換える回避策を消した。

### 3-2. L3 を Python で書く理由

**Node ではなく Python を選ぶ。** 理由は3つで、この順に重い。

1. **SQLite の中身を直接見る必要がある。** 「その会話の `parent_id IS NULL` の行がちょうど1件」（項番35）は HTTP の応答だけでは確かめられない。Python は `sqlite3` が標準ライブラリにある
2. **依存を1つも足さずに済む。** `urllib.request`（HTTP）・`http.cookiejar`（2セッションの作り分け）・`sqlite3`（DB）はすべて標準。Node で SQLite を読むには依存が要る——**描画ライブラリすら入れずに来た方針**（→[ADR-0001 技術選定](adr/0001-tech-stack.md)）を、テストのために崩さない
3. **`dev/seed.py` と `check/run.py` が既に同じ形**。読む側が学び直さなくてよい

### 3-3. 守る規約

1. **失敗したら非0の終了コード。** 既存3本と同じ形（`if (fails.length) { console.error(...); process.exit(1); }`）。人が目視で `✅` を数える形にしない。**「1」と限定しない**——`cargo test` は失敗時に 101 を返す（→項番71）。CI が見るのは0か非0かである
2. **わざと壊して終了コード1になることを確かめてから完成とする**（→項番71）。これを飛ばした検査は、通っていても意味が無い
3. **1テスト1確認。** §4 の項番と1対1にする。1つの関数に複数の assert を詰め込まない
4. **他の項番の結果に依存しない。** L3 は項番ごとに**新しい Cookie・新しい会話**から始める。DB は使い捨て（`SONAR_DB=/tmp/sonar-test.db`）で、走らせる前に消す
5. **本番と同じものを見る。** プロンプトは `src/prompt/system.md`、地図は `src/script.js` を読む。**テスト用の写しを作らない**（→[詳細設計書](detail.md) §4-8。これを破ったのが §1-1 の失敗クラス3）
6. **`docs/` を直さない。** 気づいたこと（設計からの逸脱・踏んだ罠）はセッションの出力として報告する。Vault 側に反映されて再生成で降りてくる

### 3-4. DOM スタブの既知の落とし穴

**新しい `check/*.mjs` を書くときは必ず踏む**（→[詳細設計書](detail.md) §8）。ブラウザを正しく真似ないと、**実装ではなく自分の嘘を検査することになる。**

| 罠 | 正しい真似方 |
|---|---|
| `ResizeObserver` | `observe()` で**同期発火しない**。同期発火させると `buildNodes()` の前に `place()` へ入り、`el` が空になる |
| `requestAnimationFrame` | **時計を進めないと同期再帰でスタックが溢れる**。`performance.now()` を進める |
| `cancelAnimationFrame` | **ハンドルを見る。** 無視してキュー全体を捨てると、`animateTo`（ビューの補間）が `applyLayout`（点の移動）のフレームまで消し、**点が動かないまま「動いた」ことになる** |
| `textContent = ""` | **子要素ごと消える。** `drawScale` が引き直しに使っている |

### 3-5. `src/script.js` の内部関数の取り出し方

`script.js` は module ではないので `import` できない。既存の `check/preview.mjs` と同じ手を使う。

```js
const src = fs.readFileSync(path.join(ROOT, "src/script.js"), "utf8");
const scope = new Function(src + "\n;return { tidyX: tidyX, NODES: NODES, ROOT: ROOT };")();
```

`initMap` / `initTalk` / `initPreview` は末尾で自動的に走るので、`new Function(src)()` の前に `document` / `window` をスタブしておく。

| | |
|---|---|
| `node` | **nodenv の shim にある**（`~/.nodenv/shims/node`、v24.15.0）。**非対話シェルでは PATH に載らない。** スクリプトから呼ぶときは `export PATH="$HOME/.nodenv/shims:$PATH"` を通す |

## 6. Excel テンプレートへの写し方

`inputs/テスト項目テンプレート.xlsx` の**「テスト項目書」シート**に写す。黄色のセルだけを埋め、それ以外は数式なので触らない。

| セル | 入れるもの |
|---|---|
| B3 | `Sonar` |
| B4 | `Sonar 全体（対話・保存・問いの生成・地図）` |
| B5 | 作成者名 |
| B6 | `2026/08/31` |
| A8 以降 | §4 の表を**項番順にそのまま**貼る（`### 4-1` などの節見出し行は貼らない） |

- **項番は数値で入れる。** 総項目数は `=COUNT(A8:A107)` で、数値セルしか数えない
- **C列（観点）は 正常系 / 異常系 / 境界値**、**G列（結果）は 合格 / 不合格 / 未実施** のドロップダウン。それ以外の語を入れると集計に乗らない
- **8行目の記入例（`countActive`）は上書きする**
- 数式の範囲は `A8:A107` なので**上限100項目**。現在77項目で収まっている
- G3（総項目数）・G4〜G6・I3（合格率）は数式。**手で書き換えない**
