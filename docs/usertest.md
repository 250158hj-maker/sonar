## 3. 渡すときに言うこと／言わないこと

### 言うこと

> 「いま発表したやつです。**5分くらい触ってみてください。**
> 　**途中でやめて大丈夫**です。ひとことで終わっても構いません。」

### 言わないこと

| 言わない | 理由 |
|---|---|
| 「**深く掘ってみてください**」 | §1「深掘りは降りるべき道ではなく、降りられる道」。誘導すると、測っているのが本人の意思か指示への従順かが分からなくなる |
| 「**何回か答えてください**」 | 同上。回数を目標にした時点で、浅く終わることが失敗に見える |
| 「うまく動かないかもしれません」 | 不具合を報告してもらいたいが、先に言うと粗を探す姿勢になり、自然な使われ方が見られない |

**触っている間は黙って見る。** 詰まった箇所は口を出さずに記録する。**口を出した時点で、その箇所は「1人で使えた」の証拠にならない。**

> **【重大】9/15 案は、9/9〜9/10 案より測定条件が劣化している**
> 旧版の「言わないこと」には「**『AIが問いを返します』以上の仕組みの説明**」が入っていた。
> 理由は「入口の軽さ（タップ1回）が成立しているかを見たいので、先に説明するとその検証ができない」。
>
> **発表そのものが、その説明である。** 聴衆は既にコンセプトも画面も見ている。
> したがって **9/15 の記録から「初見の入口の軽さ」は測れない。**
>
> **対処は2つ。**
> 1. **発表を聞いていない人を優先する**（他クラス・講師・家族）。1人でも混ざれば比較対象になる
> 2. **§4 に「発表を聞いたか」を記録し、所感を読むときに割り引く**
>
> **成功の定義①（地図にノードが増えたか）は、この劣化の影響を受けない。** 影響するのは所感の解釈だけである。
> ——**この劣化自体が、『プレゼン構成 20260915』 スライド9 の材料になる**（測定条件を自分で下げた記録）。

## 4. 記録（1人につき1枚）

```
実施日時    : 2026-09-15  __:__ 〜 __:__
テスター    : （匿名可。属性メモ：              ）
発表を聞いたか: はい / いいえ      ← §3 の劣化を割り引くための欄
気分の選択  : なんとなく / 聞いてほしい / もやもや / 整理したい / 選ばずに始めた

会話のターン数（＝地図に増えたノード数）: ___ 個
最も深いところまでの段数              : ___ 段
枝分かれ                              : あり / なし

地図にノードが追加されたか            : ✅ / ❌   ← 成功の定義①の判定はここだけ

【観察したこと（口を出さずに見ていて気づいたこと）】


【本人の所感（触った後に聞く）】
  ・使ってみてどうでしたか
  ・問いは、聞かれて答えやすかったですか
  ・地図を見て、何か思うことはありましたか

【不具合・詰まり】

```

> **【メモ】「辿った深さ」は記録するが、評価には使わない**
> §3 の測定方法に「辿った深さ」が入っているのは、**実施の記録として**である。
> 深く降りた人が成功で浅い人が失敗、ではない。**3人全員が浅く終わっても、成功の定義①は満たされる。**
